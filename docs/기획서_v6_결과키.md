# 기획서 v6 결과 키 표 (deck/build_v6.js ← tools/prepare_deck_data.py)

v6 기획서(편집형 30장, 디자인 원본 `deck/v6_source/build6.js`)의 결과 칸이 어느 결과 파일·열에서 오는지 적은 표다.
결과 키는 `prepare_deck_data.py` 가 `deck/data/results.json` 에 쓰고, `build_v6.js` 가 읽는다.

- 빌드: `cd deck` 뒤에
  - `npm run build:fake` → `deliverables/_test_기획서_v6.pptx` (가상 수치, 오른쪽 위 "가상 수치 · 검토용")
  - `npm run build:rehearsal` → `_rehearsal_기획서_v6.pptx` (공개 대역, 혼합 기준, "공개 대역 · 제출 금지". 기본 `REHEARSAL=gwanak_v62f` = 반입본 v6.2 번들로 돌린 공개 대역)
  - `npm run build:rehearsal:ab` → `_A.pptx`·`_B.pptx` (비교용: HBI 1.3·1.8 / 왕복 추가 5·10분)
  - `npm run build:real` → `언덕위우리동네_기획서_final.pptx` (표시 없음)
- 가드: `build:real` 은 `prepare_deck_data --expect real`(가짜·공개 대역 표지가 있으면 멈춤)과 `build_v6.js --expect real`(results.json 의 source 가 real 이 아니면 멈춤) 두 번 막는다.
- 값이 없으면 `___`(○○○) 로 두고 `deck/data/missing.txt`(공개 대역은 `missing_v6.txt`, 비교용은 `missing_v6_A.txt`·`_B.txt`)에 "누락"으로 적는다. `tools/check_deck.py` 가 pptx 빈칸과 1:1 로 맞춘다 (N = M = K).
- **later**: 공개 대역 판에서 원래 채울 수 없는 칸에 `___` 대신 보이는 말이다. missing 파일에는 "대체"로 적고, 실제 판에서는 `___`(누락) 그대로 둔다.
- 구간 기준 `--bands` (`BANDS` 환경변수). **기본 = `mix` (10/12 판정)**
  - `mix`: 체감 부담 = HBI 1.3 이상, 고립 위험 = 왕복 추가 10분 이상. HBI 1.8 은 기획서에 쓰지 않는다 (결과 파일에는 남김).
  - 비교용 `hbi`(A): HBI 1.3·1.8 / `min`(B): 왕복 추가 5·10분
  - **문턱은 mapping 한 곳에서 정한다.** 분석의 `hbi_band`(체감 부담 HBI, 기본 1.3)와 `extra_min_bands` 의 가장 큰 값(고립 위험 분, 기본 10)을 05 가 `run_meta.csv` 의 `hbi_bands`·`extra_min_bands` 에 적고, prepare_deck_data 가 그것을 읽는다. run_meta 가 없으면 1.3·10 으로 둔다.
  - 격자 단위에서는 "격자 집 절반 이상이 그 문턱 이상"으로 본다 (`share_add10m` ≥ 0.5).
- 미리보기: `python3 tools/render_deck.py <pptx> --out _render/<이름>`. 맥에 맑은 고딕이 없어 사본만 Apple SD Gothic Neo 로 바꾸고, 렌더링 전용 LibreOffice 프로필을 쓴다.

10/12 판정으로 실제 판에서 원래 비던 칸을 정리했다.
- 17장: 열을 바꿨다.
- 1억 원당 수혜: 20장(시뮬레이션한 시설)으로 옮겼다.
- 22장 사고: 법정동 단위로 채운다.
- 29장 휠체어 경사: 고정 문구로 둔다.
- 29장 엘리베이터: 09 대기시간 비교 값으로 채운다.

그래서 실제 판에서 남는 누락은 결과·입력이 없을 때뿐이다. 가상 수치판(`npm run build:fake`)은 누락 0건이다.
