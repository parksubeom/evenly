# 반출 없이 원인을 찾는 기록 (v6.2)

반출은 건마다 심사가 있어 느리고, 손메모 반출은 센터가 허용했다. 그래서 **전체 로그는 안에 두고**, 멈추면 손으로 적을 **메모 카드 다섯 줄**을 화면에 띄운다. 밖에서는 카드의 오류 번호로 정확한 코드 줄을 찾는다. 코드는 `analysis/hbi/lib/runlog.py`(표준 라이브러리만), 밖에서 찾는 도구는 `tools/lookup_error.py`.

## 안 (안심구역 PC)

| 무엇 | 어디 | 내용 |
|---|---|---|
| 전체 로그 | `hbi6/work/logs/<시각>_<스크립트>[_방식].log` | 화면 글자 그대로 (줄마다 flush, 같은 초에 또 돌면 이름 뒤에 pid). 시작 줄: 명령·판·파이썬·폴더·메모리·로그 이름. `[시:분:초]` 줄 끝에 메모리. 끝 줄: 정상/멈춤/오류/Ctrl+C·종료 코드·걸린 시간·최대 메모리·GDAL 경고 수·설정 요약. 처리되지 않은 오류는 traceback (스크립트 첫 틀부터, 값 가림). setup·check 의 질문과 친 답도 한 줄로 |
| 최근 로그 | `hbi6/work/logs/마지막.log` | 가장 최근 실행과 같은 내용. **UTF-16** 이라 949 명령창의 `type` 으로도 한글이 보임 (`notepad work\logs\마지막.log` 도 됨). run_all 이 부른 단계는 run_all 쪽에만 (run_all 로그에 단계 글자가 다 들어 있음) |
| 메모 카드 | 화면 (로그에도) | 아래 다섯 줄 |
| 요약 한 장 | `hbi6/output/run_summary.txt` (반출 대상) | run_all: 단계별 결과(정상·멈춤 코드·Ctrl+C)·시간·경고 줄 수·최대 메모리, 고른 방식, 대상 구, 방식별 의료 분석 건물 수(지난 실행 파일이면 "(이번 실행 아님)")·결과 점검표 빨강 수, 멈췄으면 멈춘 곳·오류 번호, 구조 메모(02 의 도로구분·자동차전용 코드값과 개수·남긴 링크, 코드 모양이 아닌 값은 글자 모양만). 값 없음. run_all 이 시작하자마자 "끝나지 않음" 으로 먼저 써 두므로, 앞부분 안내 멈춤·Ctrl+C·오류로 끝나도 지난번 요약이 남지 않음 |

- 진입점 17개(setup·check·run_all·01~14) 맨 위 한 줄 `import lib.runlog as _RL; _RL.start(globals())` 가 무거운 import(numpy·GDAL)보다 먼저 기록 장치를 켜고, 그 스크립트를 기록 장치 안에서 다시 실행한다 (`runpy`). 그래서 GDAL import 실패·안내 멈춤(SystemExit)·Ctrl+C 도 남는다. 기록 파일을 못 만들면 한 줄 알리고 분석은 계속한다.
- QGIS 파이썬 콘솔에서 exec 로 돌릴 때는 아무것도 하지 않는다 (파일 이름이 없음. GDAL 경고 처리기도 걸지 않아 QGIS 자신의 GDAL 글자를 건드리지 않음).
- **GDAL 경고**: `lib/qio.py` 가 GDAL 을 처음 열 때 파이썬 처리기를 건다(기록 장치가 켜졌을 때만). C 쪽에서 화면에 바로 찍던 `Warning 1: …` 이 값 가림을 거쳐 화면·로그에 남는다. 같은 경고는 3번까지만 화면에 내고 수는 끝 줄에. GDAL 바인딩은 UTF-8 이 아닌(cp949 칸 값이 든) 경고를 글자로 못 바꾸면 UnicodeDecodeError 를 걸어 둔 채 처리기를 부르므로, 그 오류에 든 원래 바이트를 cp949 로 읽어 가린다 (3.7.2·3.13.3 둘 다 확인). setup 의 인코딩 시험 구간은 원래대로 조용하다 (CPLQuietErrorHandler 를 그 위에 쌓음). run_all 은 자식 화면에서 `Warning n:`·`ERROR n:`·`proj_…:` 로 시작하는 줄을 한 번 더 가린다.
- **C 코드 충돌**(세그폴트·Windows 접근 위반): 표준 라이브러리 faulthandler 가 파이썬 줄 위치를 **그 실행의 로그 파일에만** 남긴다 (화면에는 내지 않음: Windows 의 faulthandler 는 라이브러리가 스스로 처리한 예외도 적을 수 있어 화면을 어지럽힐 수 있음. 그래서 로그에서는 마지막 블록을 씀). 혼자 돌 때는 화면에 아무것도 없이 끝날 수 있음 → **같은 명령을 다시 치면 첫 줄에 "지난번 … 은 끝 줄 없이 끝남 … 오류 번호 E04-…"** 가 나온다. run_all 아래에서는 단계가 카드 없이 끝나면 run_all 이 그 단계의 로그에서 충돌 자리를 읽어 카드를 만들고, 내용에 종료 코드(Windows 는 0xC0000005 처럼 16진수도, 맥·리눅스는 신호 번호)를 적는다.
- **문법 오류**: 단계 스크립트 자체의 문법 오류는 그 스크립트가 시작도 못 해 카드가 없으므로, `check.py` 가 시작할 때 진입점 스크립트를 모두 미리 compile 해서 걸리면 그 파일·줄로 카드를 띄운다. run_all 아래에서는 run_all 이 마지막 화면으로 카드를 만든다.
- `output/runlog/`·`output/diagnose.txt` 는 v6.2 부터 쓰지 않는다 (로그를 위한 별도 반출 없음). v6.1 이 같은 hbi6/ 에 남긴 것은 run_all 이 시작할 때 `work/logs/v61_runlog/` 로 옮긴다 (지우지 않음).
- **반출 대상 결정**: `check_report.txt`·`setup_report.txt`·`result_check.txt`·`schema/` 는 그대로 반출 대상 (값 없는 점검 결과. 화면 사본 성격이지만 v6 부터 반출해 왔고, 받은 자료 구조·폴더 이름은 다음 번들 맞춤에 필요). 값이 섞일 수 있던 곳(머리줄 없는 CSV 의 첫 행)은 v6.2 에서 막음 → 아래 '값 가리기'.

### 메모 카드

```
==== 메모 카드 (아래 다섯 줄만 적어 오면 됨 · 반출하지 않아도 됨) ====
  1 오류 번호 : E12-Q73S9F   (hbi_code v6.2 #b1f643)
  2 단계      : 12_isochrone.py (부른 곳 12_isochrone.py:54)
  3 오류 종류 : FileNotFoundError
  4 내용      : FileNotFoundError: [Errno 2] No such file or directory: 'work/network.npz'
  5 할 일     : 파일·폴더 주소 확인 (python setup.py 를 다시 하면 config.py 를 채움)
  (전체 기록: notepad work\logs\마지막.log  - 반출하지 않음)
============================================================
```

- **오류 번호** `E<단계>-<6자>`: 단계 = 스크립트 앞 두 글자(01~14) 또는 SU(setup)·CK(check)·RA(run_all). 6자 = 우리 코드 안에서 오류가 난 가장 안쪽 파일·줄과 **판의 내용 해시**(VERSION 의 `#…`, 번들에 든 .py 전부의 sha1 앞 6자)로 만든 5자(25비트) + 확인 1자. 32자 표(헷갈리는 I·L·O·U 없음).
  - 확인 글자는 GF(32)(다항식 x⁵+x²+1) 가중합(가중치 2·3·4·5·6, 확인 글자 1)이라 **한 글자 틀림과 이웃 두 글자 바뀜을 모두 잡는다** (표본 3,000개, 놓침 0).
  - 같은 판·같은 위치면 늘 같은 번호, 판이 다르면 다른 번호 → 밖에서 다른 판으로 찾으면 엉뚱한 줄 대신 "찾지 못함".
  - 가장 안쪽이 `lib/` 이면 2 단계 줄에 "부른 곳 <스크립트>:<줄>" 을 덧붙인다 (경로·줄 번호는 가리지 않음).
  - 안내 멈춤(`raise SystemExit("… → …")`)은 그 줄, check 의 멈춤은 처음 `stop()` 을 부른 줄(예외를 받아 멈추면 그 예외가 난 줄). check 의 카드 내용·할 일은 첫 멈춤의 글자 (여러 건이면 "외 N건").
  - run_all 이 부른 단계가 멈추면 카드는 그 단계 것 하나만 (run_all 은 자기 카드를 띄우지 않음). run_all 중 Ctrl+C 면 단계 줄이 "04_validate.py 실행 중 (run_all)", 할 일이 "python run_all.py --from 04".
- **할 일**: 안내 멈춤이면 그 안내의 `→` 뒤. 알려진 오류는 오류 종류로 판단 — 메모리 부족(numpy 의 _ArrayMemoryError 포함), config.py 문법 오류("config.py 의 N줄 확인 … 안 되면 config.py.bak 을 config.py 로 복사 → python setup.py". 번들을 다시 풀면 setup 이 채운 경로가 사라지므로 그렇게 안내하지 않음), 다른 코드 파일 문법 오류(번들 다시 풀기 → setup), 칸 이름 KeyError(가려지지 않은 = 아는 칸 이름일 때만 mapping 안내), GDAL·numpy import 실패, 파일 주소, 글자 형식. 그 밖에는 "이 카드를 적어 오면 밖에서 찾습니다".

## 밖

- `python3 tools/lookup_error.py <오류 번호> --bundle deliverables/hbi_code_bundle_<판>.txt` → 파일:줄, 그 줄을 품은 함수, 앞뒤 4줄, 안내 멈춤이면 그 안내. 번호 계산은 **그 번들 안의 lib/runlog.py 와 VERSION 해시**를 그대로 쓴다. `--rev <git 판>` 은 그 판의 .py 로 같은 내용 해시를 계산, `--src <폴더>` 는 그 폴더(VERSION 이 없으면 개발판).
  - 하이픈·띄어쓰기는 빼도 됨, 5자·확인 쪽의 O→0·I·L→1·U→V 는 자동으로 고침 (단계 쪽 SU 는 그대로).
  - 확인 글자가 안 맞거나 그 번호가 없으면 한 글자 틀림·이웃 두 글자 바뀜 후보, 그래도 없으면 헷갈림 표(0↔D/Q/G/8, 1↔7/T, 2↔Z, 5↔S, 6↔G/E, 8↔B, 9↔G, M↔N/W, V↔Y)로 바꾼 후보를 찾는다. 아무것도 없으면 "적을 때 틀렸거나 판이 다름".
  - 맞은 자리가 진입점 스크립트인데 카드의 단계와 다르면 "(단계와 맞지 않음)" 으로 뒤에 둔다.
- 번들을 만들면(`tools/build_bundle.py`) `hbi6/VERSION` 에 `hbi_code <판> #<내용 해시>` 를 넣고, 커밋하지 않은 변경이 있으면 경고한다. `docs/오류번호표_<판>.md` 도 생김: 안내 멈춤 자리(SystemExit·check 의 stop·'→' 안내가 든 raise)마다 번호 뒤 6자·파일:줄·안내 글자 (runlog·tools, 정상 끝 `SystemExit(0)`·글자 없는 `sys.exit(…)` 은 뺌).
